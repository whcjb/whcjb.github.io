# old-book-ocr

一部 19 世纪的扫描件，ABBYY 跑完仍有 0.5%–2% 的词是错的。这个量级靠人眼逐页
读不现实（诗篇 34 万词、以赛亚 63 万词），靠规则硬改则必然越修越坏。

本 skill 记录的是在亚历山大《诗篇注释》（34.3 万词，非词率 0.78% → **0.28%**）
与《以赛亚书注释》（63.4 万词，1.72% → 1.61%）上跑通的做法。两本书的
差异本身也是结论的一部分：**同一条规则在一本书上完全正确，换一本书会毁掉
几十处**，见 `refs/traps.md` 第一条。

---

## 0. 一句话方法论

> **每加一道修复能力，就要配一道守卫；守卫的职责不是把错的改对，
> 而是让「本来会改错」变成「不改」。**

留在账上的残字是可见的、可再查的；改错的字是**静默**的——它成了一个合法
英文词，判词典不认它有问题，读者也看不出来。所以所有判据都往「宁可不判」
一侧偏。全流程 20 余轮改动、累计 1500 余处落盘，靠这条原则做到**回退 0 处**。

## 1. 四层证据

按强度排序，上一层解决不了才用下一层。每层都有各自的失效区，谁也替代不了谁。

| 层 | 证据 | 能解决 | 失效在哪 |
|---|---|---|---|
| ① 字形规则 + 判词典 + 语料自证 | **词频**证据 | 成套的连字误读（`li→U` `ff→fi` `rn↔m` `w→iv`） | 只说明这个词书里有，不说明**这一处**就是它 |
| ② 第二证人按位置判读 | **位置**证据 | 规则穷举不到的乱读（`Imows→knows` `xmder→under`） | 锚撞车会读出隔壁的词；两版之间的改写会被误当误读 |
| ③ 页面影像 | **最终**证据 | 两份 OCR 在同一处都读崩的 | 贵；且只能告诉你原文是什么，读不出非拉丁活字 |
| ④ 换引擎重扫 | **换传感器** | 希伯来／希腊活字（拉丁引擎根本读不出） | 同形字映射；带元音点的希伯来文读不出 |

**第 ② 层是主力**，能清掉大头。第 ③ 层单位成本高（约 7 处／批影像），
只用来清第 ② 层判不动的残余。第 ④ 层是另一条路：不是「判读得更准」，
而是**换一个能看懂这种字的传感器**。

详细判据、实测阈值、在哪本书上量的 → `refs/gates.md`

**这四层的前提是「已经有一份文本」**。第一手文本由哪个引擎、从哪份底本产出，
决定了四层要干多少活 → §2

## 2. 引擎选型：在四层之前

四层证据讲的是「**已经有一份文本之后**怎么清」。那份文本从哪来、由谁产出，
决定了后面四层要干多少活——而这个决定常常被当成默认值一带而过。

### 2.1 先挑底本，再挑引擎

同一本 19 世纪的书，IA 上常有十来份扫描件，**彼此错词率的差距比换引擎还大**。
做法：把每份的 `_djvu.txt` 拿判词典跑一遍，按非词率选，数据记进 `PROVENANCE.md`
（以赛亚书的 uoft 1846/47 两卷就是这么从十来份里挑出来的）。

**这是整条链上性价比最高的一步**：挑底本几乎免费，换引擎要重跑全书。

### 2.2 有可信文本层就不要重 OCR

| 来源 | 文本层 | 怎么办 |
|---|---|---|
| AGES / CCEL 数字排版 PDF | 就是原文，无 OCR 误差 | **走抽取，不走 OCR** |
| ABBYY XML | 带斜体、字号、坐标 | 三类里最好的输入（诗篇／以赛亚） |
| IA 扫描件自带的隐形层 | tesseract 生成的 `GlyphLessFont` | **必须重跑** |

IA 那层要专门警惕：字体一律 `GlyphLessFont`，**不含任何字形信息**——小型大写
全塌成小写（`EPISTLE TO THE COLOSSIANS` → `to the colossians`）、词间双空格、
错字偏多。版面判据里凡是要用字号／坐标／斜度的，这层一概给不了。Davenant
就是因为这个从 PDF 重渲染重扫的。

### 2.3 硬规矩：正文一律由非生成式引擎产出

生成式模型读不清时会顺着上下文**编一个通顺的词**，错得像真的，人工校对发现
不了；传统引擎读不清只吐乱码，错误留在明面上可检可修。神学文本里一个 `not`
被「补」没了整句意思就反了。这条不因模型变强而松动，只改变它能站在哪个位置
（见 §2.6）。

### 2.4 候选引擎

| 引擎 | 适用 | 代价 |
|---|---|---|
| **ABBYY FineReader** | 19 世纪清晰印本；要斜体／字号／坐标时首选 | 商业；版面分区不可控 |
| **tesseract**（tessdata_best） | 通用基线；可脚本化、可按页按通道跑 | 行分割弱，旧书行距不均时最先崩的一环 |
| **Kraken / eScriptorium** | 行级 CTC + **可训练的版面分割**；欧洲古籍项目的事实标准 | 要准备 ground truth |
| **Calamari** | 多模型投票的行识别器（本 skill 的多证人思路，人家做进引擎里了） | 同上 |
| **OCR-D** | 16–19 世纪印本的整套工作流规范，分割／识别／后校可替换模块 | 重；以德语／拉丁印本为主 |
| **Transkribus** | 有 17–19 世纪印本的公开模型，支持拿自己的 GT 微调 | 商业、云端 |

后四项属于 historical OCR 这一支，和通用 OCR 是两个生态。它们对旧印本的优势
集中在：长 ſ、`æ/œ/ﬆ/ﬁ` 连字、磨损铅字、小型大写，以及**行分割**。

### 2.5 tesseract 实测配置

Hodge 罗马书与 Davenant 歌罗西书上量过的：

- **渲染**：`get_pixmap` 原生分辨率，或固定 400 dpi。**不要上采样**——实测
  锐化和放大都会变差。
- **去噪**：`cv2.medianBlur(3)`。OOV 率 8.6% → 6.0%。
- **参数**：`--psm 4`，模型用 `tessdata_best`。
- **语言包按需最小化**。Davenant 用 `eng+lat`；加上 `grc` 会把小型大写页眉
  `Ver. 3.` 读成希腊字母 `Ρεν, 8.`。**零散的非拉丁活字走第 ④ 层单独裁图重扫，
  不要指望主通道兼顾**——为几十个希腊词加一个语言包，代价是几百个页眉。
- **字形信息单开通道**：斜体角度、字号、词级坐标各跑一遍 hOCR 存 jsonl，
  主通道只管文字。⚠️ 改页面范围时**所有通道的页码范围要一起改**，否则新页的
  斜体全丢，而闸子不报。

### 2.6 生成式 VLM：可以用，但永不进产物

2025–2026 这一批专做 OCR 的 VLM（dots.ocr、olmOCR、MinerU、PaddleOCR-VL、
Mistral OCR）比通用 Qwen-VL 强得多，强在**版面**：直接给出带阅读顺序的分区
——脚注区、双栏、表格、缩排。这恰好是手写几何判据最费力的部分。但失败模式
没变：读不清时补一个通顺的词。

**允许的两种位置**：

1. **当第 ② 层的一份证人**：只用来**报告分歧位置**，分歧处回到影像定夺，
   它给的文字不落盘。
2. **出页级版面标签**（「这一页大半是编者长注」「这一页是半标题页」）。
   标签错了看得见，文字错了看不见——这就是它能不能用的分界线。

**禁止**：拿它的输出当正文；拿它「补」读不清的词。

### 2.7 什么时候真该换引擎

先把残留分成两类问一句：**剩下的错是「认不出字」还是「版面／切分」？**

- **认不出字**（连字、长 ſ、磨损铅字、c/e 成片混淆）→ 换历史印本引擎或微调
  有用。
- **版面／切分**（脚注区边界、跨页续注、斜体判角、行归属、页面归属）→
  **换引擎一点忙帮不上**，这些是自己写几何判据的活。

Davenant 收尾时 319,358 词剩 9 处残留，这 9 处里只有一类属于字符识别，
换引擎最多省一两处。**先分账，再决定要不要为它重跑全书。**

### 2.8 尚未动用的一档：拿自己的校勘结果去微调

一本校完的书就是同一套铅字、同一台扫描仪、同一个 dpi 下**最好的 ground
truth**。`tesstrain`（微调 tesseract 的 LSTM）或 Kraken 微调，通常几十页 GT
就能把 CER 压进 0.1% 量级。它专治**同一台设备的系统性错误**（c/e 那一类），
而这正是字典后校正治不了的——后者只能修「不在词典里、且在固定混淆映射下
候选唯一」的词，`heard`/`beard` 这种真词互换它碰不到。

**成本不在训练，在重跑**：改了第一手文本，下游全部重来。Davenant 一个 token
的 OCR 小修就触发整段重译，重译还可能在别处退步。所以这一档**只在开一本新书
时考虑，不要回头给已收尾的书换引擎**。

## 3. 流水线与顺序

```
extract  ABBYY XML → 章节 markdown（斜体、分段、页码、连字符）
   ↓
repair   字形规则 + 判词典 + 语料自证（第 ① 层）
   ↓
publish  → 已发布正文（front matter、节号锚点）
   ↓
adjudicate --apply   第二证人判读 + 手工表 + 重扫落盘（第 ②④ 层）
```

**三条顺序上的硬约束**（违反任何一条都出过事，见 `refs/traps.md`）：

1. **产物层的修正必须能一条命令全量恢复。** 判读与重扫的结果只存在于已发布
   正文里，`publish` 一跑就没。把它们落成**规则表**（而不是直接改产物），
   由 `adjudicate --apply` 统一应用，才能在任何一次重跑之后恢复。
2. **排在 token 阶段之前的文本级规则，都要先问一句「字形规则表对这个串
   有没有解」。** PRE 阶段跑在 RULES 之前，不问这一句等于抢在修复之前下结论。
3. **已有结论的桶不再被后续判据覆盖。** `handsoff`/`manual` 被 `fragment`
   覆盖之后，账目上会把「查过、是对的」错记成「还没查」。

## 4. 验收口径

每一轮改动都要过这四关，缺一不可。

### 4.1 逐词比对 + 自动回退判据

```python
# 旧串每个词都是真词、新串出现非词 = 越改越坏
if all(is_word(x) for x in old_words) and not all(is_word(x) for x in new_words):
    回退
```

这条能自动抓出绝大多数「改坏了」。**比对要对着上一个已知良好的提交**，
不是对着 HEAD——HEAD 可能已经被别的会话改过。

### 4.2 幂等性

`--apply` 跑到不再产生新判决，再跑一次应无变化。不收敛说明规则在互相打架。

### 4.3 规则自检

手工表是按整句字符串匹配的，上游一改就**静默失效**。每条规则记命中次数，
原文与修复后的形态**都找不到**时报警——只看「没命中」会在幂等重跑时误报。

### 4.4 渲染层校验

正文对不等于页面对。五项，都很便宜：

| 查什么 | 怎么查 | 抓到过什么 |
|---|---|---|
| 渲染丢词 | 逐篇过 kramdown，比对渲染前后的实词集合 | 野生 `<` 被当标签、从这里吃到下一个 `>` |
| 斜体跑飞 | 渲染后 `<em>` 内容首尾是否带空白 | 归一化没迭代到不动点 → `*1 *mutual` → 星号一路开着 |
| 锚点总数 | 每轮比对，数字必须稳定 | 抽取端合段规则把整节并掉 |
| 重复锚点 id | `id="…"` 计数 | 同一 id 出现多次，页内跳转跳错位置 |
| 斜体星号奇偶 | 剥标签后数 `*` | 规则多插／少插一个星号 |

**在 markdown 层面数星号是数不清开闭的**（`*a* 正文 *b*` 里中间那段会被
误算成一个强调），只能看渲染后的 `<em>`。

## 5. 换一本书时怎么做

1. **先定底本与引擎（§2）。** 挑底本几乎免费，换引擎要重跑全书——顺序反了
   就只能将就着清。
2. **先量，再用。** 任何从别处拿来的清理规则，先在本书上跑一遍看命中什么。
   同一条规则在以赛亚书上完全正确，在诗篇上会拆坏 43 处。
3. **阈值要重新量。** `refs/gates.md` 里每个数字都注明了在哪本书上量的。
   相似度下限、语料门槛、拼词长度差，都随书的错误谱变。
4. **先分账，再排期。** 把可疑 token 分成「已核实原样／外文与活字残渣／
   待判」三类，待判再按「证人有话说／证人对不上／无证据」分档。
   分类判据**不能用「有没有元音」**——希腊文与希伯来文的拉丁转写元音一点不少，
   用它会把待判量高估一倍。
5. **证人有几份，决定了能走多远。** 单证人时锚撞车必然留下一条读数，只能靠
   形状闸事后拦；多证人的多数表决会让撞车时票数分散，噪声在判决**之前**
   就被筛掉。
