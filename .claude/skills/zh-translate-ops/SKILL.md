# 中译批次运行规范

## 一、铁律：翻译出问题，先停下

> 用户 2026-11-03：「翻译出问题，要先停下，解决问题，彻底解决完之后再继续翻译，不要随意乱翻。」

出现下列任一情况，**立刻停掉翻译**，不许边跑边修、不许「先跑完、被拦的篇排到后面再补」、不许接着开下一本书：

- 监视到 `⛔ [篇] 有段落重试后仍不合格`（篇被拦）；
- 同一类 `retry-struct` 在不同段反复出现（说明是系统性问题，不是偶发）；
- 抽查发现已写出的译文有错（漏译、自语、占位符错乱、空括号、术语前后不一……）；
- 额度用尽（exit 42）——这时进程已自己停，**不要**立刻排队重跑。

**停的做法**（缺一步就等于没停）：
1. `pkill -f "translate_<书>.py"`；
2. 停掉排队的等待脚本（`pkill -f "while kill -0"` 之类）；
3. 杀掉孤儿 claude CLI 子进程（父进程为 1 的 `claude … --system-prompt`）；
4. 确认 `pgrep -fl translate_` 为空，`.git/index.lock` 不存在。

## 二、彻底解决 = 找到这一类、修在源头、验证过

1. **查原因到「类」**：不是只看被拦的这一段——问「还有哪些段会因同一原因出错」。
   例：`probationē` → `probationem` 被判漏译，根因是判据只认 ASCII 字母，同类还有 `Excōmunicatio`、`mendaciū`、`vitâ`……
2. **修在源头**：判据 / 提示词 / 发布脚本，不改产物了事；同一套闸在
   `translate_jenkyn / taylor / attersoll / candlish`（以及 davenant 的 `check_block`）里一并修。
3. **回归验证（两条都要过才算修好）**：
   - 拿**全部已缓存译文**跑新旧判据，比对结论：新增误报必须为 0（误报会让已合格的段在重发时被重译）；
   - **注入测试**：随机抽几百块已有译文，往中文里插常见英文词（the / however / Keep / Translation / Italic……），
     新判据必须全部抓出（2026-11-03 这样查出斜体内漏译 84/397 全漏抓）。
4. **单独重跑被拦的那一篇**，确认 `✓ 写入` + `[autopublish] 已提交并推送`，再看一眼产物。
5. 修判据、提示词的提交与产物提交分开写清楚；把这次的根因记进本 skill 第四节。

全部做完，才恢复批次。

## 三、开跑与恢复

- **只跑 1 路**（`--jobs 1`，一次一本书）；多路、多本并行须用户当次明说。排队用等待脚本时按**进程号**等（`while kill -0 <pid>`），
  不要用 `pgrep -f "translate_… --section"`——等待脚本自己的命令行就含这串字，会永远等下去；取不到 pid 时不许启动（曾因此并发跑出第二个进程）。
- **去掉无关上下文**：调用一律走 `translate_filibi.call_claude → claude_usage.call_cli`，自动带
  `--safe-mode --strict-mcp-config --disallowedTools '*'` + `--system-prompt`（不发工具定义、MCP、CLAUDE.md、skills）。不要自己拼 subprocess。
- **新书开跑前**：查有无正式中译本（有就不做）；试跑统计篇数 / 段数 / 字符并估价告诉用户；**先试译一篇短的**抽查，再放开全书。
- **恢复**：`--resume` 只补没缓存的段；已写出、缓存齐且过闸的篇自动跳过。
- 监视器只报 `✓ 写入 / ⛔ / Traceback / 额度`；到期就重挂。

## 四、已踩过的坑（判据与产物）

| 现象 | 根因 | 处理 |
|---|---|---|
| 希腊词尾成拉丁字母 `ἀποδιορίζοντES` `δένδρa` | 模型输出 | `restore_greek`：原文里前缀同、长度同、按形近字母对回唯一的词才换回 |
| `Answer with the bare translation alone.` / 开头「答案：」 | 只有标题的占位符块被当问答 | 「模型自语」判据（英语虚词 ≥2）+ `tidy` 去前缀 |
| 正文里夹着推敲：`This is an index entry` `Rule: don't wrap only a number` `Hmm` `Quote Scripture…`（各书约 3–6% 的调用） | 模型没有地方想，引经文、斜体、索引条、旁注、页眉这类要判断的段就边想边写 | **换机制**：要求把译文装进 `<译文>…</译文>`，`take_tagged` 只取标签内（标签外随它说）。回放 24 段曾自语的原文：不加标签 4 段不合格；开 CLI 原生思考（`alwaysThinkingEnabled`）仍 4 段、自语反增、贵 36%，**不要再试**；加标签两遍 48 次 0 段。闸子照旧把关标签内 |
| `probationē` / `Excōmunicatio` / `ipsâ vitâ` 被判漏译 | 拆词只认 ASCII | 字符集扩到 À-ɏ；印本断词接回只认含音标的相邻两词拼合 |
| 斜体里的漏译抓不到 | 斜体一律放行 | 斜体内遇常见英语词且原文没有 → 拦 |
| 页面上空括号「比喻（）」 | 模型给页边旁注外加括号 | 发布脚本去掉只裹旁注的括号 |
| 短条目表（索引、教义表）反复被拦 | 一句话的块模型爱自语 | 跑到这类篇时多看一眼；仍按铁律停下处理 |
| 段首冒出 🧠 ⓘ ╋ ℰ 零宽空格、错字「징兆」、制表线「─」 | 模型吐垃圾字符（多在短条目表段首） | `odd_chars` 白名单判据：名单外且原文没有即拦；夹在 `*​*` 间的零宽空格有用、放过 |
| 目录页（全书纲目）编号「一、/第三讲/XV./[四、…]」混用、链接指英文页 | 结构化目录交给模型自由排版 | 发布脚本按固定格式重排（`publish_candlish_zh.fix_contents`）；**目录类页面一律程序生成格式，不信模型排版** |
| 原文把同一节经文引了两次（约翰一书第 27 讲诗 66:18–20：先直引、再在古人语录里复引），三次重试都判「重复起稿」整篇被拦 | 重复句判据只看中文，不看原文本来就重复 | `scripture_repeat`：原文有连续 6 词以上的重复片段，**且**中文重复句是和合本原句（`assets/cuv.json` 去标点串）才放行；其余照旧拦。回归：8,104 块缓存新增误报 0；注入非经文重复 544 处全抓 |
| 页面残留 `<译文>`；回归又捞出已上线的 `Running header: …` 英文自语、只译出一个「面」、段首 `<br>` / `<|i|>` | 模型把开标签写两次；尖括号标记不在任何判据里 | `take_tagged` 取最后一个开标签之后；「残留标签」判据（译文有原文没有的 `<…>`）。**每加一道新判据都拿全部缓存跑一遍**——这次 8,611 块捞出 4 块早已发布的坏译文 |
| 「父从亡古以来」——生僻字写成形近常用字（亘→亡） | 模型逐字生成时偶发；质检原先不查用字 | `KNOWN_TYPOS` 已知错字表（发现一个收一个）+ 提示词写明正确写法；统计式形近扫描误报太多，只作人工辅助 |
| 分条孤句（「5. Lastly, The right manner of…」）译出来夹着 `Context… irrelevant… instructions` | 一句话的块模型看不到上下文，就在输出里自语（佩特第 1 章 3 次同类） | **短段（<300 字符）附前后段英文**，明说只供理解、不译不输出；缓存键只取本段、不受影响。回放 24 次 0 不合格；另加「上下文泄漏」判据 |
| 第一遍偶发只吐几十 token 的废话（`<reasoning_effort>`、`Placeholder →`、只剩一个字） | 模型随机故障，与段落内容无关：同段重放 15 次全合格，复现不出；约 0.4% 的调用。stop_reason 是正常的 end_turn（不是截断）；一次原样输出「尽是 Claude Code 自动附带的上下文。」——多半是模型去回应 CLI 仍会附带的少量系统上下文 | 结构闸照拦、重译一次即好，**不算系统性问题**；第一遍的原始输出写进 issues log 备查。若重译也连坏才按铁律停 |
| 占位符不符 `[1..6] → [1,2,5,6]`：一对相邻占位符整对丢失（罗洛克帖前 4-13#8、4-16#5，约 383 次调用 2 次） | 原书分页标记是空标签 `<span class="rl-pb" …></span>`，`mask` 把开、闭标签各编一号，成了中间没字的 `⟦3⟧⟦4⟧`，模型偶尔当成无用记号删掉 | 2026-11-09 罗洛克已修：`mask` 加 `RE_EMPTY`，空标签对合成一个占位符。**缓存键取的是遮盖后的原文、缓存存的是遮盖后的译文**，改 mask 等于换键——必须同时迁移旧缓存（`scripts/rollock_migrate_mask_v2.py`：旧 tags 还原→新 mask 重遮→比对占位符→写新键，旧文件不删），否则 `--resume` 会重译。回归：627 段新旧判据均 0 不合格、新增误报 0、还原后译文逐字一致；注入删空对占位符 447/447 抓出。其他 12 个 translate_*.py 同款 mask 未改，开跑前照此办 |
| 「叙事本身**未提供**足够的材料」三次被判「模型在对话」整篇被拦（亚历山大使徒行传 9#20） | `CHATTY_RE` 收了裸词 `未提供 / 没有附上 / 无法翻译 / 你似乎`——都是正当译文常用词（加尔文祷文「你似乎一时将我们抛弃」也中） | 2026-11-09 收紧为「讨原文」搭配（`未提供(任何)?(原文|文本|英文|内容|需要翻译…)`、`(您|你)似乎(没有|忘|只…)`），18 个 translate_*.py 同改。回归：15.1 万块缓存新增误报 0、旧误报 8 处放行、真对话 4 处仍抓；注入 3000 次全抓。顺带查出欧文希伯来书 exercitations/34 中文页已上线一段「请提供需要翻译的英文原文。」待重译 |
| 「原文没有的希腊词」在不同段反复被拦（亚历山大使徒行传 4#8 补介词 ἐν、15#14 给西缅/西门括注 Συμεών/Σίμων、18#23 补词尾 ας；5#3 是词中冒 U+FFFD 的偶发乱码，另一类） | 提示词只说「希腊文逐字照抄」和「专名括注英文原名」，没说**不许添**；模型懂希腊文，讲到语法、碰到圣经人名就顺手补 | 2026-11-10 按铁律停批次；13 个 translate_*.py 的照抄条款后加「原文里没有的希腊文、希伯来文一个字母也不许添（专名括注只写英文原名）」。缓存键不含提示词，已译段不重译。回放 3 段 × 3 次 0 不合格（$0.33）。johnstone 原已有同义条款；hutcheson/perkins 无希腊文条款未加 |
| 改译名时把页面形态（`<span class="dv-orig">`）写进了缓存 | 页面与缓存形态不同，批量替换没分开 | 缓存/成品用圆括号形态、页面用 span 形态，分开替换；改完全缓存跑 `check_block` 复核 |
